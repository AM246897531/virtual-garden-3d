# משנה תורה — אפליקציית Android מקומית

This feature branch implements a private, fully offline Android Mishneh Torah reader and source-finder. The app requires no internet or AI account after installation.

## Coverage and edition integrity

At build time, `scripts/build_corpus.py` downloads the Sefaria export and uses only specific legally labeled Torat Emet (Public Domain) or Wikisource (CC BY-SA) editions. Each of the 83 halakhic sections is checked chapter by chapter and accompanied by per-edition provenance. The verified build has 14 books and 15,063 **actual, nonempty** halakhot in SQLite, searchable with FTS4.

**Important numbering note:** Hilchot Talmud Torah, chapter 7, halakhah 8 is intentionally empty in the common printed editions: it is a documented numbering skip, not missing source text. It is recorded under `numbering_anomalies` and does not create a fabricated extra law. Evidence: [Wikisource](https://he.wikisource.org/wiki/רמב%22ם_הלכות_תלמוד_תורה_ז), [Mechon Mamre](https://mechon-mamre.org/i/1307.htm). Any other truly missing passage fails the corpus build.

`corpus_report.json` generated by CI is the authoritative report for each APK. Contents such as the introductory material, mitzvot lists and prayer-order appendix are not within the current 83 halakhic sections; do not equate 83-section coverage with every front/back matter text.

## Tiny local learned Hebrew search model

At build time, `scripts/build_semantic_index.py` trains an **80-dimensional Hebrew Word2Vec skip-gram model** on the licensed local Mishneh Torah corpus and learns character-subword representations for unseen query forms. It exports `hebrew_semantic.bin` (about 6 MB), with learned vocabulary and an indexed embedding for each halakhah. The native Kotlin `SemanticIndex` runs the model's embeddings offline, combining its similarities with exact FTS4 retrieval and Hebrew variant ranking. No cloud, LLM, external model downloads or ONNX library is required on the phone.

This is **small domain-specific neural retrieval**, not an independently pretrained foundation model, and should not be expected to understand arbitrary modern Hebrew as well as a large multilingual embedding model. It **does not generate psak or make up answers**. All results are direct quotes and precise source references.

## Build

Prerequisites: Python 3.11, Java 17, Android SDK 35, Gradle 8.10.2. To rebuild the identical code with current source editions:

```bash
python -m pip install requests==2.32.3 numpy==2.1.3 scipy==1.14.1 gensim==4.4.0
python scripts/test_corpus_utils.py
python scripts/build_corpus.py
python scripts/build_semantic_index.py
python scripts/test_semantic_index.py
gradle :app:assembleDebug
```

GitHub Actions executes the full sequence and additionally tries an emulator screenshot smoke test. The signed debug APK is installable but is **not** a release-signed Play Store package. Consult `BUILD_AND_TEST_REPORT.md` in the delivered build artifact to verify the emulator test outcome. The UI includes RTL browsing, search, bookmarks, reader controls and light/dark modes.


## v0.3.0 — reliable smart question search
- Query submissions are debounced (650ms) with an immediate search action and keyboard IME Search; cancellation of superseded lookups is not displayed as an error.
- Each query runs against the bundled Hebrew semantic embedding index and indexed local Mishneh Torah database. No runtime network or API calls.
- High-precision matching of common natural-language halakhic questions points to source halakhot rather than generating a ruling.
- The top result displays the **complete, unaltered Rambam text and exact citation** directly; other relevant sources follow.
- Existing installations migrate their SQLite corpus automatically on the first launch of this version.
- GitHub Actions checks multiple real Hebrew questions and simulates character-by-character typing to guard against the previous race condition.

This is local *retrieval*, not a generative rabbinical model. The source text should be read in full and contextualized.

## v0.4.0 — snippet evidence, 50-question quality gate and faster source search

- The search result now visually highlights a bounded, question-relevant **verbatim** passage from the law and continues to display its complete text. The law reader also highlights and scrolls to it. Highlighting is explicitly marked as approximate and does not replace reading the full context.
- Selection combines token/clause matching, a high-precision topic anchor (if applicable), and locally learned Hebrew term-vector similarity. Unrelated text is not forcibly highlighted if there is insufficient evidence.
- Real Android emulator tests now execute `scripts/quality_50.json` through the same `CorpusStore.search()` and `relevantPassage()` used by the UI. The 50 questions include direct, paraphrased and moderately compound queries. An independent exact book/chapter/law expected answer is declared for each. **The workflow must fail unless all 50 return the expected top reference and all 50 locate a non-empty passage**. This is a curated regression sample, not evidence that all possible halakhic questions are answered correctly.
- Search work has been reduced: prefix-FTS now fetches candidate row IDs first, law texts are loaded once in batches, and nearest-semantic retrieval maintains a bounded top-K heap instead of sorting all 15,063 laws. Typing debounce changed from 650 ms to 380 ms. The test log reports median and P95 retrieval latency on the emulator (not network or first-install time).
- The model is **not a generative LLM**; its only output is source retrieval. The developer should not claim it constructs autonomous halakhic rulings.
